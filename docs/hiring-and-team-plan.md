# Hiring and Team Plan

## Team-Building Goal

Build a team that can deliver campaign workflows, analytics, optimization, and operational reliability without relying on a single engineer as the system memory. Hiring should follow the product maturity curve: complete the core product first, then deepen reliability, data, and enterprise capabilities.

## Target Team Shape

| Role | Timing | Primary impact |
| --- | --- | --- |
| Full-stack product engineer | First hire | Accelerate campaign workflow and dashboard delivery |
| Backend/platform engineer | Early | Strengthen API design, reliability, auth, and data integrity |
| Frontend engineer | Early to mid | Improve advertiser workflows, accessibility, and UI quality |
| Data/ML engineer | Mid | Mature analytics, CTR prediction, and recommendations |
| QA/automation engineer | Mid | Expand regression coverage and release confidence |
| DevOps/SRE partner | Fractional or mid | Production readiness, observability, incident response |

## Hiring Priorities

1. Hire for product execution and strong engineering fundamentals first.
2. Add backend/platform depth before scaling enterprise commitments.
3. Add data/ML specialization once analytics data contracts and reporting needs are clearer.
4. Add dedicated QA or SRE capacity when release volume and operational load justify it.

## Interview Loop

| Stage | Signal |
| --- | --- |
| Recruiter or manager screen | Motivation, communication, scope fit |
| Technical screen | Coding fundamentals and practical problem solving |
| System design | Service boundaries, tradeoffs, reliability thinking |
| Product collaboration | Ability to clarify ambiguous product requirements |
| Values and teamwork | Ownership, feedback, inclusive collaboration |

Interview rubrics should be written before interviews begin and calibrated after each hiring cycle.

## Onboarding Plan

First week:

- Run the local stack.
- Read README, phase docs, roadmap, and ADRs.
- Walk through campaign creation and status transitions.
- Pair on one small documentation or test improvement.

First month:

- Own one vertical slice from frontend through backend.
- Participate in review and release readiness.
- Add or improve one runbook, metric, or test path.
- Meet product, engineering, and operational stakeholders.

First quarter:

- Own a roadmap feature or platform improvement.
- Present one technical decision or post-implementation review.
- Identify one improvement to team delivery or maintainability.

## Growth and Performance

Expectations should be explicit by level:

- Junior engineers grow through scoped delivery, testing discipline, and code review participation.
- Mid-level engineers own features end to end and identify operational risks.
- Senior engineers lead ambiguous work, mentor others, and improve architecture.
- Staff-level contributors shape cross-service direction and reduce systemic risk.

## Team Health Signals

Monitor:

- One-on-one themes and recurring blockers.
- Review load and response time.
- Unplanned work percentage.
- Incident load and after-hours burden.
- Onboarding time to first meaningful contribution.
- Psychological safety signals from retrospectives.

## Manager Practices

- Hold weekly one-on-ones with clear follow-up.
- Protect focus time and reduce priority churn.
- Make tradeoffs visible when scope, quality, or timeline conflict.
- Recognize both feature delivery and operational improvements.
- Use retrospectives to improve systems, not assign blame.
